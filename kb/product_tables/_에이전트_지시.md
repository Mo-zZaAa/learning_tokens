# 회사 개요 카드 JSON 만들기(상품별, Ondo 카드와 같은 모양)

목표: kb/<slug>_overview/<slug>_overview.json 하나를 쓴다. 사이트 개요 탭 1층이 이 파일을 그대로 그린다(Ondo가 이미 이 방식).

## 읽을 것(이 순서)
1. 본보기 카드: kb/ondo_overview/ondo_overview.json 의 "card" (행 label, items, kids, table, path, flow, strong, danger, note 쓰는 법)
2. 본보기 그림: kb/flows/ondo_flows_v2.json (rich 그림: title, rich:true, head, stages[name, badge[글, earn|zero], arrows, boxes[[이름, 설명, 종류]], sum], footbox, legend)
3. 내용 원본(가장 중요): kb/product_tables/sheets/<slug>.txt = 사용자가 직접 만든 상품 x 질문 표(엑셀 시트를 칸 좌표와 함께 옮긴 것). 열 D~H가 상품, 행이 질문(이 사업은 뭔가, 누구에게, 무슨 인가, 누가 무엇을 맡나, 돈은 어떻게, 뭘로 버나, 전체, 언제 생겼나, 주의할 점, 그 밖의 상품), 아래에 확장 경로, 법인 구조, 파트너십, 용어
4. 보충: kb/cards6/<slug>.md(한 화면 카드, 질문과 답), kb/cards/<slug>.md(긴 개요), kb/structs/<slug>/*.csv, 필요하면 db/facts.csv(회사 열로 거르기). 새 웹 조사는 하지 않는다

## JSON 모양
{"card": {"name": "회사 이름", "sub": "나라, 한 줄 정체(무엇에서 무엇으로)", "rows": [...]}, "flows": {"<키>": {rich 그림}, "revenue": {"title": "...", "table": {"head": [...], "rows": [[...]]}, "foot": ["..."]}}, "sources_new": []}
- 줄: {"t": "글", "strong": true(큰 줄일 때), "kids": [줄...], "table": {"head": [...], "rows": [[...]]}, "flow": "그림 키"}
- 근거 번호(F-0000, on-0000 같은 태그)는 붙이지 않는다. "tags" 키를 아예 쓰지 않는다
- 확장 경로 행만 "path": [{"k": "상품 확장", "t": "A(연도) → B(연도) → ...", "kids": [...]}, {"k": "고객 확장", ...}, {"k": "시장 확장", "sub": [{"k2": "(해외자산)", "t": "..."}, {"k2": "(해외고객)", "t": "..."}], "kids": [...]}, {"k": "법인과 인가", "t": "...", "kids": [{"t": "법인 정리", "table": ...}]}, {"k": "파트너십", "t": "...", "kids": [{"t": "파트너 정리", "table": ...}]}]

## 행 순서(label 그대로)
1. "무엇을 하나": 큰 줄 1~2개. kids로 어떤 회사, 장터인가 아닌가, "밸류체인에서 <회사>가 맡는 칸" 표(head: 단계, 무슨 일, <회사>가 하나, 누가 하나)
2. "KDX가 볼 이유": 큰 줄 3~4개. 첫 줄은 KDX와의 관계(판단). 나머지는 "그래도 볼 이유 n: ..." 형식. 성과는 숫자로. 회사를 주식 토큰 순위로 평가하지 않는다
3. "상품별 표": 줄 하나 {"t": "상품 n갈래를 같은 질문으로 나란히(기준 시점)", "open": true, "table": ...}. 표 head = ["질문", 상품1, 상품2, ...](시트의 D~H 열 상품 이름), rows = 시트의 질문 행(이 사업은 뭔가, 누가 누구에게 파나(파는 쪽, 사는 쪽, 회사 자리: 직접 판매, 자기 거래소, 중개, 남의 상품 진열. 남이 파는 상품을 회사가 파는 것처럼 쓰지 않음), 무슨 인가로 하나, 누가 무엇을 맡나, 돈은 어떻게 오가나, 뭘로 버나(비중), 언제 생겼고 어떻게 바뀌었나, 주의할 점). 칸은 짧은 문장 2~3개를 ". "로 이음(줄바꿈 없음). 시트 내용을 그대로 쓰되 너무 긴 칸은 줄임
4. "사업 영역": 상품마다 큰 줄 하나(strong 아님, Ondo처럼 "상품 이름(시작 연월~): 한 줄 정의. 버는 방식") + kids(투자자나 손님이 가진 것, 누가 무엇을 맡나, 버는 방식과 1,000달러 예시, 인가, 주문은 어디로, 사용자가 시트에 적은 Q와 답은 kids 줄 "질문?: 답" 형식으로) + "flow": "<상품 키>". 마지막 줄은 {"t": "<회사>가 돈을 버는 시점과 돈이 쌓이는 곳", "note": true, "flow": "revenue"}
5. "숫자": 큰 줄 4~6개(매출 구성, 연도별 매출과 이익, 고객 수, 자산, 자금 조달) + kids로 "그게 뭔데"에 답
6. "확장 경로": path(위 모양). 시트의 확장 경로, 법인 구조, 파트너십 표를 옮김
7. "배울 점": KDX가 배울 것 4~6개(자산, 고객, 시장, 거래 시설 운영 순서). "KDX가 볼 이유"와 겹치지 않게. 피할 것은 kids에 "피할 것: ..."
8. "주의할 점": {"label": "주의할 점", "danger": true, "items": [...]} 4~6개

## 그림(flows) 규칙
- 상품마다 rich 그림 하나(키는 영어 소문자, 예: spot, futures, staking). "rich": true 필수
- title "<상품>: <손님>이 1,000달러로 ...할 때", head "돈 흐름 한 줄: A → B → C, <회사> 몫 ..."
- stages 3~4개: 회사 사업에 맞게(예: ① 주문, ② 체결, ③ 들고 있는 동안, ④ 팔거나 돌려받을 때). 각 단계 badge는 ["<회사> 몫: 무엇", "earn"] 또는 ["0" 또는 짧은 글, "zero"]
- boxes 2~4개: [이름, 설명 1~2문장, 종류]. 종류: "ondo"=<회사> 그룹 법인과 <회사> 몫(보라), "ext"=외부 회사(초록), "inv"=손님이나 투자자(회색), "none"=관여 없음(점선)
- arrows: 상자 사이 화살표 "r"(→), "l"(←), ""(없음). 길이 = 상자 수 - 1
- sum: 그 단계 결론 한 줄(숫자는 계산식과 (계산) 또는 (판단))
- footbox: "돈이 쌓이는 곳: ..." 한 줄, legend: "보라 = <회사> 그룹 법인과 <회사> 몫, 초록 = 외부 회사, 회색 = 손님, 점선 = 0이거나 공개 안 됨"
- 숫자 예시는 공개 숫자로 계산한 것만(예: 분기 매출 ÷ 분기 거래대금). 지어낸 요율 금지

## 글 규칙(어기면 실패)
- 한국어, 명사형이나 ~함/~임 종결. 구어체 금지
- 긴 줄표(—, –), 가운뎃점(·) 금지. 대신 쉼표나 괄호
- 금지어: 제공, 지원, 확대, 강화, 통합, 연결, 운영사, 발행 대행, 백단, 미확인, 확인 필요, 미정(모르면 빼거나 "공개 안 됨")
- 회사 지표 이름(총플랫폼마진 등)은 뜻을 먼저 풀고 이름은 괄호에만. 직역 금지. "그럼 그게 뭔데"가 남는 줄은 답하거나 뺌
- 해석과 짝짓기는 (판단), 계산은 (계산). 날짜는 발표, 완료, 출시를 구분. 숫자마다 기준 시점
- 비유를 쓰면 원어를 괄호로(예: 상품권 발행사(issuer))
- 사람 이름 중 PM, 사용자 본인, 동료 이름은 쓰지 않는다
