# 회사 전략 틀(화면과 파일 제목은 "<회사>의 전략", 옛 이름 스토리라인) (Kraken 기준, 2026-11-17 PM 확인)

브리핑 파일 맨 위, 1층 앞에 둔다. 예시는 briefs/Kraken.md의 "## <회사>의 전략".

## 절 구성(순서 고정, 회사에 없는 절은 한 줄로 "해당 없음"과 이유)
1. 출발 : 무엇으로 시작했고, 본업 옆에 처음 붙인 것과 제도권에 들어선 계기
2. 자산 : 어떤 자산을 왜, 어떤 방법(직접, 인수, 파트너)으로 붙였나. 오래 걸린 것은 왜 오래 걸렸나. 앞의 확장이 다음 상품의 기반이 된 연결
3. 비전 : CEO와 회사가 밝힌 방향(기관, 기업, 결제 등)과 실제로 붙이는 중인 것, 다른 회사와의 차이 한 줄
4. 시장 : 거점, 큰 시장, 규제가 엄격한 시장을 각각 어떤 방식(무인가 판매, 직접 인가, 인수, 파트너)으로 들어갔나. 자산 순서와 공개 목표
5. 정체성 변화와 당국 관계 : 무엇에서 무엇으로 바뀌는 중인가, 그 근거(전후 비교)
6. KSF : 반복된 성공 방식(대상, 운영 방식, 효과, 기준)
7. 가설 : 모회사나 소유 구조 같은 특성이 속도나 방향에 준 영향(전부 "해석")

## 문체
- 문장 끝은 "~함", "~됨", "~임", 이유는 "~하기 때문" 또는 괄호.
- 사건을 나열하지 않는다. "그래서", "그 결과", "같은 흐름에서", "이렇게 갖춘 ~을 바탕으로"로 앞의 일이 다음을 어떻게 가능하게 했는지 잇는다.
- 처음 나오는 회사, 법인, 제도, 약어는 바로 뒤 괄호로 무엇인지 한마디(예: GTN(여러 나라 상장주의 주문 집행과 수탁을 맡는 증권 중개 그룹)).
- 추론은 "해석 :"으로 시작하고 근거 사실을 붙인다.
- 줄마다 근거 [F-xxxx](원문 링크). 링크는 db/facts.csv 링크 칸 그대로.
- 라벨은 명사형(제공 내용, 이용 기업, 운영 방식, 선정 기준). 질문형 라벨("무엇을 파나") 금지.
