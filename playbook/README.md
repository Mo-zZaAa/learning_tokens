# 플레이북: 피드백을 지침으로, 리서치를 노하우로

이 폴더는 사용자 피드백과 리서치 경험을 쌓아 다음 작업에서 다시 쓰는 곳이다. 이 저장소의 모든 작업(메인 세션, 하위 에이전트, 로컬 세션)은 시작할 때 아래 두 파일을 먼저 읽는다.
- playbook/writing_rules.md: 쓰기 지침(피드백에서 뽑은 규칙)
- playbook/research_knowhow.md: 리서치 노하우(막힌 곳과 통한 공식 경로, 쓸모 있던 1차 출처 위치, 도구, 함정)

## 피드백 한 회차가 올 때마다 하는 일(순서 고정)
1. 메모마다 답하고 본문, DB, 용어를 고친다. discussion/log.jsonl에 한 줄씩 남긴다.
2. 메모를 유형별로 묶어 "왜 이 질문이 나왔나"를 한 줄씩 적는다(lessons_log.md의 새 회차).
3. 그중 다른 회사, 다른 작업에도 해당하는 것을 writing_rules.md 규칙으로 더하거나 고친다(규칙 끝에 회차 번호).
4. 같은 유형의 줄을 다른 회사 본문에서도 찾아 미리 고친다(사용자가 같은 질문을 두 번 하지 않게).
5. 리서치 담당의 knowhow_inbox/*.md를 research_knowhow.md에 합치고 inbox 파일은 지운다.
6. 다음 지시문(브리프)은 이 두 파일을 참조하고, 그 회차에만 해당하는 것만 따로 쓴다.

## 하위 에이전트에게 일을 줄 때
- 브리프 첫 줄: "playbook/writing_rules.md와 playbook/research_knowhow.md를 먼저 읽는다."
- 리서치, 쓰기, 다듬기는 다른 에이전트로 나눈다(쓰는 사람이 자기 글을 검수하지 않게).
- 다듬기 담당은 처음 보는 독자로 읽고, writing_rules.md 각 항목을 점검표로 쓴다.
