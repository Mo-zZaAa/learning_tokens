# KDX 해외 사례 웹 화면 제작 지시 (리서치가 끝난 뒤 실행)

리서치 결과(`db/`, `companies/`, `kb/`, `captures/`)가 저장소에 있다. 이것으로 사용자가 읽고, 묻고, 합의한 내용을 쌓아 두었다가 한 번에 내보내는 화면을 만든다. 배치를 나눠 만들고, 배치가 끝날 때마다 커밋하고 푸시한 뒤 다음 배치로 넘어간다. 질문하려고 멈추지 않는다.

## 1. 형태

- 파일 하나로 열리는 HTML(`web/index.html`). 자료는 파일 안에 넣는다. 서버와 외부 라이브러리 주소에 기대지 않는다.
- 자료가 바뀌면 `web/build.py`를 다시 돌려 같은 파일을 새로 만든다.
- 글은 쉬운 한국어. 긴 줄표와 가운뎃점 기호를 쓰지 않는다.
- 본문은 간결하게 보이고, 세부와 근거는 줄을 눌러야 나온다.

## 2. 배치

| 배치 | 만들 것 |
|---|---|
| 1 본문 | 회사 고르기. 7개 대분류 본문을 ●, ★, ① 들여쓰기로 표시. 줄을 누르면 근거(원문 근거 문장, 링크, 출처 종류, 검증 상태, 열람일)와 본문에서 뺀 세부(법인 전체 이름, 인가 기관, 발표일). 용어를 누르면 쉬운 뜻과 헷갈리는 짝 |
| 2 밸류체인 지도 | 가로는 상품 공급, 체결, 청산, 결제, 기록, 고객 접점, 투자자. 세로는 전통증권, 토큰증권, 가상자산, 파생상품 및 기타. 칸에는 시작 연도, 하는 일, 법인. 연도 막대와 재생 단추로 해마다 칸이 채워지는 모습. 운영 중과 발표, 계획은 진하기로 구분. 회사 두 곳 나란히 보기와 전체 회사 겹쳐 보기 |
| 2-1 등록 지도 | `db/licenses.csv`로 가로가 하는 일(고객 접점, 체결, 청산, 결제, 기록, 보관), 세로가 회사인 표. 칸마다 직접 등록, 인수, 제휴로 빌림을 구분해 표시(색이나 기호). 칸을 누르면 보유 법인, 등록 종류, 감독기관, 관할, 시점, 등록부 링크 |
| 3 관계 | 모회사, 자회사, 주요 주주를 지분율과 함께 나무 모양으로. 인수, 제휴, 발행과 유통 위탁은 선으로. 이름 검색 |
| 4 제도와 ATS | 쟁점별 한미 제도 비교 표(조문 링크 포함). ATS 후보와 선정 사유 표 |
| 5 대화 축적과 내보내기 | 3절과 4절 |

## 3. 대화를 쌓는 방식

질문은 두 길로 들어온다. 둘 다 같은 기록에 쌓는다.

- 화면에서: 줄마다 의견 칸. 종류는 `풀어쓰기 요청`, `이해 확인`, `딥다이브 요청` 셋. 줄 문구 고치기, 줄 추가와 삭제, 순서 바꾸기, 확정 표시, Securitize와 tZERO 추가 확인 표시(주황)도 화면에서 한다. 내용은 브라우저에 저장하고, `의견 내보내기` 단추로 `web_comments.json`을 내려받는다. 사용자가 이 파일을 저장소 `inputs/`에 올리면 읽어서 처리한다.
- 이 세션에서: 사용자가 직접 묻는다.

질문 하나를 처리할 때마다 아래를 모두 한다.

1. 쉬운 말로 답한다. 새로 찾은 사실은 리서치 지시문의 규칙(링크, 근거 문장, 검증)을 그대로 따른다.
2. 같은 질문이 다시 나오지 않도록 본문, DB, 용어를 고친다.
3. `discussion/log.jsonl`에 한 줄을 더한다: 시각, 회사, 대분류와 중분류, 질문 종류, 질문, 답 요지, 고친 곳, 근거 fact_id, 상태(답함, 합의, 보류).
4. 화면을 다시 만든다.

## 4. 내보내기 (다른 대화의 Claude에게 넘길 묶음)

화면의 `최종 내보내기` 단추와 `web/export.py` 둘 다 같은 묶음 `export/handoff_to_chat.zip`을 만든다. 받는 쪽은 이 묶음만으로 엑셀을 채운다.

| 파일 | 내용 |
|---|---|
| `final/<회사>.json` | 확정 본문. 대분류 순서대로 줄 목록. 줄마다 `level`(`●`, `★`, `①`), `text`, `color`(`black` 또는 `orange`), `fact_ids`, `confirmed`(사용자가 확정했는지) |
| `final/captures/` | 원문 캡처 이미지. 어느 줄 아래 들어가는지 json에 파일 이름으로 연결 |
| `discussion_log.md` | 회사별, 시간순으로 질문, 답, 고친 내용 |
| `open_items.md` | 아직 합의되지 않은 줄과 남은 질문 |
| `glossary.md` | 본문에 쓰인 용어의 쉬운 뜻 |
| `line_sources.csv` | 본문 줄마다의 링크와 검증 상태 |
| `regulation_compare.csv` | 쟁점, 미국 제도(근거 법령), 국내 제도(근거 법령), 차이에 따른 결과 |
| `ats_candidates.csv` | ATS 후보와 선정 사유 |

- 엑셀 틀의 배치: 대분류는 색 띠, `●`는 B열, `★`는 C열, `①`은 D열. 병합 없음. json의 줄 순서가 곧 행 순서다.
- 본문 규칙은 그대로다: 중분류마다 3~4줄 이내, 한 줄 40자 이내, 한 줄에 메시지 하나, 확인된 내용만.
- 맨 위 요약(기업 정의, 조사 목적, 조사 내용, Summary)은 내보내지 않는다. 사용자가 직접 쓴다.

## 5. 화면에서 지킬 것

- 본문에는 검증 상태가 `1차 출처 확인`이나 `교차 확인`인 줄만 보인다. 나머지는 회사별 `검증 대기` 목록에 따로 둔다.
- 판단(성공요인, 시사점)은 근거가 된 사실이 함께 보여야 한다.
- 사용자가 확정한 문구는 다시 만들 때 덮어쓰지 않는다.

## 6. 끝났을 때 보고

- 화면 여는 방법, 배치별로 만든 것, 못 만든 것과 이유.
- `export/handoff_to_chat.zip`을 한 번 만들어 형식이 맞는지 확인한 결과.
