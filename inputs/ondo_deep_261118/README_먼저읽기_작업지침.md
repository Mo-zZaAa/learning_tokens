# Ondo 깊이 보기 페이지 작업지침 (Claude Code용)

## 0. 한 줄 목표
- KDX 사이트에 "Ondo 깊이 보기" 페이지를 새로 만듦
- 대상 독자: 이 분야 이해도가 낮은 컨설턴트(PM 보고 준비 중). 휴대폰으로도 읽음
- 기준: 페이지만 읽고도 아래 `content/질문_커버리지.csv`의 모든 질문에 답할 수 있어야 함. Q&A 목록으로 따로 빼지 말고 그림과 설명 안에 녹일 것

## 1. 이 패키지 안에 든 것
| 경로 | 무엇 | 쓰는 법 |
|---|---|---|
| `content/ondo_본문.md` | 섹션별 본문 원고. 위계(대불렛, 소불렛, 접힘 세부)와 그림 지시가 들어 있음 | 페이지 문구의 원본. 사실 문장은 그대로 쓰고, 표현만 다듬을 것 |
| `content/질문_커버리지.csv` | 사용자가 지금까지 한 질문 전부와, 답이 들어갈 섹션 ID | 완료 검사표. 모든 행이 페이지 어딘가에서 답해져야 함 |
| `content/용어사전.csv` | 용어, 쉬운 설명, 비유와 원문 병기 | 본문에서 용어를 누르거나 손가락을 대면 뜨는 설명 팝업용 |
| `data/*.csv` | 차트와 표에 쓸 데이터. 행마다 출처 ID와 신뢰도 표시 | 차트 원본. 4번 "데이터 보강" 절차로 채울 것 |
| `data/sources.csv` | 출처 ID, 제목, 링크, 신뢰도 | 페이지 하단 출처와 문장별 각주 링크 |
| `reference/엑셀초안_*.xlsx, .py` | 직전에 만든 엑셀 초안과 그 원문 데이터 | 내용 참고만 할 것. 사용자가 보기 어지럽다고 해서 폐기한 형식임 |

- 출처 표기 규칙
  - `on-XXXX`: 사이트 DB(site_data.json)에 이미 있는 Ondo 행 ID. 원문 인용(q)과 링크(url)는 DB에서 끌어올 것
  - `S-xxx`: 이번에 새로 확인한 웹 출처. `data/sources.csv`에 있음
  - `OV`: Claude Code가 만든 Ondo 개요 md(사이트 Ondo 개요 원고)

## 2. 페이지 구조 (위에서 아래 순서, 섹션 ID 고정)
- 모든 섹션은 3층 구조로 만듦
  - 1층(항상 보임): 헤드 메시지 한 줄 + 그림 1개
  - 2층(항상 보임): 그림을 읽는 법, 핵심 숫자 3~5줄
  - 3층(+ 눌러 펼침): 근거, 세부, 비유, 판단, 출처
- 상단에 섹션 목차를 고정. 각 섹션 헤드 메시지를 목차 문구로 씀

| ID | 섹션 | 1층 그림 | 답하는 대표 질문 |
|---|---|---|---|
| S1 | Ondo는 무엇을 하나 | 상품 4개 + ONDO 토큰 카드 그리드(누가 사나, 안에 든 것, 금고 주인, 보유자 권리, Ondo 수입) | 뭐하는 애들인가, Intelligent Portfolios가 상품인가 |
| S2 | Ondo는 상품마다 무슨 역할을 하나 | 역할 매트릭스(행: 상품, 열: 발행, 운용, 보관, 담보 대리, 판매 창구, 거래 시설, 인프라). 칸 색: Ondo 직접 / 재단 쪽 계열 / 제3자 / 해당 없음 | 발행사, 인프라사, 거래사, 운용사 정체성을 나눠 갖나, 아예 안 하는 곳은 |
| S3 | 법인 지도 | 소유 구조도(재단 쪽, 회사 쪽, 발행 법인, 제3자 4색). 화살표에 지분율과 관계 표시 | 법인이 왜 이렇게 많나, 재단은 왜, 케이맨과 BVI는 뭔가, 9.99%는 왜 |
| S4 | 법인을 나눈 이유 5가지 | 이유 5개 카드 + 각 카드에 해당 법인과 생긴 시점 | 인가 때문인가, 언제부터 왜 |
| S5 | 금고는 누구 금고인가 | 금고 주인, 금고지기, 열쇠 하나 더(담보 대리인), 보유자 권리 4칸 그림 | 금고는 누구 것, Ankura는 무슨 일 |
| S6 | 상품별 돈 흐름 | 상품 4개 각각 세로 순서도. 가상 숫자(1,000만 원, 1,000달러) 따라가기 | 실제로 돈이 어떻게 움직이나, Coinbase는 어디 끼나 |
| S7 | OUSG가 담은 펀드 4개 | 비중 막대 + 펀드 4개 비교표 + 구성 변화 누적 막대(시점별) | 펀드 4개는 각각 무엇, 왜 나눠 담나 |
| S8 | 뭘로 돈 버나 (이익 원리와 비중) | 상품별 이익 원리 도식 + 분기별 매출 막대(DefiLlama) + 상품별 추정 이익 분해(판단, 회색) | 발행 자체 이득은, 이익 비중은, 이익 원리는, 본사로 오나 |
| S9 | 상품 크기와 점유율 변화 | 상품 4개 잔액 선 그래프(시점별) + 점유율 추이 + "잔액이 뭔지" 설명 카드 | 잔액이 무슨 의미, 성과와 비중 변화 데이터 |
| S10 | 연혁 (단을 나눈 타임라인) | 가로 레인 타임라인. 레인 6개: 상품, 법인과 인가, 판매 지역과 창구, 인프라와 기술, 이름과 브랜드, 경영과 자금 | 이름을 바꾸고 상품을 내고 어느 쪽에서 무엇이 바뀌었나, 발행 법인 세우기 전에는 무엇을 했나 |
| S11 | 규제 용어 풀이: 면제, Regulation S, EU 투자설명서 | 판매 지역 지도형 그림(미국, 미국 밖, EU, 아부다비, 한국)과 각 지역 판매 근거 | 면제는 뭔가, Reg S는 뭔가, FMA 승인하면 뭐가 달라지나 |
| S12 | 주의할 점 | 위험 5개 카드 | 무엇이 위험한가 |
| S13 | 출처 | 섹션별로 묶은 출처 목록(누르면 열림) | 모든 사실의 링크 |

## 3. 그림과 화면 규칙
- 그림은 HTML/SVG로 직접 그림. 이미지 파일 금지(글자 검색과 수정이 안 되므로)
- 색은 의미에 묶어 4가지만 씀. 페이지 전체에서 같은 뜻에 같은 색
  - 회사 쪽(Ondo Finance Inc.와 그 아래): 파랑 계열
  - 재단 쪽(Ondo Foundation, Flux Finance): 주황 계열
  - 발행 법인(Ondo Global Markets (BVI) Limited): 노랑 계열
  - 제3자(계약 상대): 회색 계열
  - 상품 칩만 초록 계열 허용
- 범례는 그림마다 맨 위 한 줄
- 휴대폰 폭(약 380px)에서 그림이 가로로 넘치지 않게 세로로 쌓이는 배치를 기본으로 함. 넓은 화면에서는 가로 배치
- 용어 팝업: `content/용어사전.csv`에 있는 용어가 본문에 처음 나오면 점선 밑줄. 누르면 쉬운 설명 + 비유(원문 병기) 팝업
- 판단 문장: "(판단)"으로 시작하고 회색 글씨. 확인된 사실만 검정
- 출처: 사실 문장 끝에 작은 번호 각주, 누르면 원문 인용과 링크
- 펼침(+): `details/summary` 또는 같은 동작. 기본은 접힘. 상단에 "모두 펼치기, 모두 접기" 버튼

## 4. 데이터 보강 절차 (S7, S8, S9 차트용)
- 지금 `data/` 안 숫자는 출처가 섞인 시드 데이터임. 아래 순서로 보강하고, 차트에는 출처와 기준일을 반드시 달 것
- 1순위: DefiLlama 공개 API
  - `https://api.llama.fi/protocol/ondo-finance` 에서 일별 TVL과 하위 상품(토큰)별 값을 받음. 하위 프로토콜(국채 상품, Ondo Global Markets 등)이 따로 있으면 각각 받음
  - 매출: DefiLlama fees 화면의 분기별 Gross Protocol Revenue(`data/revenue_quarterly.csv` 시드)와 같은 값을 API에서 받음. DefiLlama의 fees, revenue, holders revenue 정의를 차트 아래 한 줄로 적을 것
- 2순위: rwa.xyz 공개 화면 숫자(Treasuries, Stocks 리그 표)
- 3순위: Ondo 홈페이지와 블로그, 보도자료에 나온 시점별 숫자
- 신뢰도 낮음(`confidence=low`) 행은 1~3순위로 같은 시점 값을 찾으면 교체하고, 못 찾으면 차트에서 뺌
- OUSG 구성 변화: 시점별 구성 공시가 있는 시점만 점으로 찍고, 그 사이를 이어 그리지 말 것
- 상품별 이익 분해는 공시가 없으므로 계산식과 가정을 그대로 보여 주고 전부 회색 (판단) 처리

## 5. 문체 규칙 (사용자 고정 규칙, 하나라도 어기면 다시 할 것)
- 한국어. 개조식, 명사형 종결(~함, ~임). 슬로건, 구어체 금지
- 대시(—)와 가운뎃점(·) 금지
- 동사 "제공"을 쓰지 말 것(맡음, 둠, 팖, 내줌 등으로)
- 비유를 쓰면 반드시 원문 용어(실제 명칭, 영문 원어)를 함께 적음
- 어려운 말은 쉬운 말로 풀고, 원리부터 차근차근
- "미정", "미확인", "~여부 확인 필요" 같은 쓰나마나한 문장 금지. 모르는 것은 빼고, 판단할 수 있으면 (판단)으로 확정안 제시
- 숫자는 기준일을 붙임
- 사실은 확인된 출처가 있는 것만. 지어내지 말 것
