F.13. Technology and
Blockchain
Information on the
Distributed Ledger
technology used, including
Technology (DLT)
distributed ledger technology
describes a decentralized
and distributed network
system architecture where
multiple participants
maintain and verify a
shared database. Unlike
traditional databases, DLT
systems do not rely on a
central authority to ensure
data consistency and
security. Rather, they
distribute control across a
network of computers
(nodes) and require all
changes to be recorded
and agreed by the nodes.
58

This distributed approach
enhances the resilience
and security of such a
system, and transparency
of the data stored in it
without the need for trust
between the actors of the
systems.
Blockchain technology is a
subset of DLT, where the
distributed database
maintains a continuously
growing list of records,
called blocks, which are
linked together in
chronological order and
secured using
cryptographic techniques.
A blockchain generally
has the following key
characteristics:
● Distribution: A
blockchain
operates on a
network of nodes,
each holding a
copy of the ledger
and each
participating in the
transaction
verification and
synchronization
process.
● Security:
Blockchain
employs
advanced
cryptographic
methods to secure
data. Each block
contains a
cryptographic
hash (a ‘digital
fingerprint’) of the
previous block, a
timestamp, and
transaction data.
This structure
ensures that once
data is recorded, it
cannot be altered
retroactively
59

without also
changing all
subsequent
blocks, which
would require
consensus from
the majority of the
network nodes.
● Transparency and
Immutability:
Transactions on a
blockchain are
usually visible to
all participants in
the network,
providing
transparency.
Once a
transaction is
confirmed and
added to the
blockchain, it is
virtually
immutable due to
the cryptographic
methods used,
meaning it cannot
be changed or
deleted.

Introduction
U2U Network (also known

with native token “U2U”) is
a Layer-1 public

launched in 2023,
designed to be scalable,
efficient, and optimized for

The project emerged from

U2U is built as an
independent distributed

blockchain infrastructure
60

(not relying on third-party

decentralized physical

(DePIN) and enterprise

The U2U Network’s
architecture is based on
an advanced Directed
Acyclic Graph (DAG)
ledger structure combined
with a unique consensus
protocol (described
below), rather than a
traditional linear
blockchain. This
DAG-based approach
allows multiple
events/transactions to be
processed in parallel,
contributing to high
throughput and fast
finality.
U2U’s Native Token, U2U
The native crypto-asset of
the U2U Network is the
U2U token (ticker: U2U). It
is the unit of value on the
ledger and is used for
transaction fees, staking,
and on-chain governance
within the U2U ecosystem.
Holding U2U enables
participation in the
network’s Delegated
Proof-of-Stake consensus
(either by running a
validator node or by
delegating tokens to
validators, as explained
below), and token holders
can vote on governance
proposals affecting the
protocol’s development
and parameters. The U2U
token also serves as the
medium of exchange for
transferring value on the
61

network and can be
utilized in decentralized

protocols, liquidity in

Helios Consensus
Mechanism
The U2U Network uses a
proprietary consensus
protocol called Helios,
which is a blend of
Asynchronous Byzantine
Fault Tolerance (aBFT)
and Delegated
Proof-of-Stake (DPoS)
techniques. In Helios,
network participants
(token holders) either
operate validator nodes
themselves or delegate
their stake (U2U tokens)
to trusted validators.
DPoS means that a limited
set of validators are
elected by token stake
votes – those with the
highest stake (including
delegated tokens) become
responsible for producing
and validating blocks (or
DAG events) on behalf of
the broader network. This
greatly reduces the
number of nodes needed
to reach agreement at any
time, improving
throughput. aBFT means
the system can tolerate
malicious or failed nodes
and still reach consensus
on transactions without
assuming reliable
message delivery times –
it does not rely on
perfectly synchronous
communication.
62

U2U’s Helios algorithm
achieves consensus
asynchronously, ensuring
that even if messages are
delayed, honest nodes will
eventually agree on the
order of transactions. This
provides robustness
against network delays
and malicious actors. In
practice, Helios divides
time into small units and
uses a DAG structure to
allow consensus to form
without a single leader
proposing each block;
instead, validators gossip
transactions and
collectively decide
ordering. The combination
of DPoS and aBFT allows
U2U to finalize
transactions very quickly
(with block finality typically
well below 1 second) while
maintaining strong
security guarantees.
Staking and Delegated
Proof-of-Stake
U2U employs a Delegated
Proof-of-Stake model,
meaning U2U token
holders secure the
network by staking tokens
and either becoming
validators or delegating
their stake to validator
nodes. Validators are
nodes that produce blocks
(or add transactions to the
DAG) and participate
directly in the consensus
protocol. To encourage
only serious,
well-resourced
participants as validators,
U2U requires a significant
minimum self-stake (for
example, on the order of
1,000,000 U2U as a
baseline commitment).
63

Validators are responsible
for running full nodes,
processing transactions,
and executing smart
contracts, and they must
meet hardware
requirements to handle
the network’s high
throughput. Delegators
are token holders who do
not run a node themselves
but contribute to network
security by staking their
U2U tokens with a chosen
validator. By delegating,
they essentially vote for
that validator to be part of
the active validating set;
the weight of each
validator in consensus
(and its chance to produce
blocks) is proportional to
the total stake it controls
(self-stake + delegated
stake). This process
incentivizes
decentralization by
allowing many token
holders to participate in
securing the ledger, even
if only indirectly.
Staking on U2U is
designed to be flexible
and rewarding. Tokens
can be staked and
unstaked at any time (with
a short unbonding period
– currently unstaking
requires a 7-day unlock
before tokens become
transferable). U2U also
offers an optional lock-up
feature: delegators may
choose to lock their staked
tokens for a fixed period
(between a minimum of 14
days up to a maximum of
365 days) to earn higher
rewards. Longer lock-up
durations yield greater
reward rates as an
incentive for long-term
64

network commitment.
However, if a delegator
unlocks their stake before
the agreed lock period
ends, a penalty is applied
– typically, the delegator
forfeits a portion of the
accumulated rewards (e.g.
they might receive only
half of the base reward,
and the remaining portion
of the reward is burned as
a penalty). This
mechanism encourages
stable staking and aligns
participants with the
network’s long-term
success.
To maintain network
reliability, validators are
expected to remain online
and performant. U2U
enforces penalties for
validators that are
excessively offline or fail
to sign blocks. For
example, if a validator is
down for more than a
certain threshold (e.g.
1000 consecutive missed
blocks or 5 days of
downtime), the network
can mark the validator as
inactive and potentially
slash a part of its rewards.
This ensures that only
responsive and secure
nodes participate in
consensus. Honest
behavior is further
incentivized by the reward
structure (detailed below
in H.5), wherein validators
and their delegators earn
regular staking rewards for
securing the network, as
long as they uphold the
protocol rules.
Layered Architecture
U2U’s architecture is
modular and multi-layered,
65

designed to separate
concerns and improve
scalability and
interoperability.
Conceptually, the platform
can be described in
multiple layers or
components:
○ Networking and
Communication
Layer: At the
base is a
peer-to-peer
networking layer
connecting all
U2U nodes. It
handles message
propagation, DAG
event sharing,
and validator
coordination. This
layer is optimized

environments and
asynchronous
consensus,
ensuring that

consensus mechanism, be summarized as a
where applicable reputation-augmented Delegated

BFT finality. This mechanism was

U2U Network utilizes a Delegated

achieve agreement on the ledger
state asynchronously. Validators
are randomly rotated or selected
in a manner influenced by their
stake and a verifiable random
function, ensuring no single
validator can monopolize block
production. Because the protocol
is asynchronous BFT, it can
tolerate network delays and still
reach finality without requiring
strict timing assumptions,
improving robustness against
network partitions or DDoS
attacks.
A key aspect of Helios DPoS is its
focus on fast finality and high
throughput. Blocks (or events)

confirmed by the consensus are
finalized in under one second on
average, meaning users achieve
near-instant confirmation of
transactions. The network is
designed to handle thousands of
transactions per second by
leveraging parallel validation in
the DAG – for example, each
shard or subnet of the network
can process on the order of
17,000 TPS, and overall network
throughput scales with additional
resources. This is a substantial
improvement over traditional
single-chain proof-of-work
systems, aligning with U2U’s goal
of enterprise-grade scalability.
Security in the consensus is
ensured by economic incentives
and the aBFT design. Validators
must put up a large stake (and
often have many delegators’
stakes assigned to them), which

maliciously (slashing can be
applied in cases of double-signing

consensus tolerates up to f faulty
or malicious validators out of 3f+1

network remains secure unless a
supermajority of stake (over 67%)
