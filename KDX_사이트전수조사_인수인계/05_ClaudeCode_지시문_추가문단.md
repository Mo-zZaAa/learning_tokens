## 조사 틀, 사실 원장, 관계 데이터

### 무엇을 채우는가

- 조사 항목은 `조사틀과_관계도/out/10_조사틀_개편안.md`의 대분류 8개와 소분류다. 사용자의 관심사 7개를 겹치지 않게 다시 묶은 것이다.
- 회사마다 A 출신과 진입, B 상품 구조, C 최종 투자자, D 유통과 접점, E 인가를 채운다. F 관계와 G 한국 접점은 해당 있을 때만 쓴다. H 제도와 시장은 회사별이 아니라 한 번만 정리한다.
- 읽기 담당(site-pack-reader)에게 넘기는 조사 질문도 이 소분류 목록이다.

### 이미 확인된 것은 다시 조사하지 않는다

- `조사틀과_관계도/out/12_사실원장.csv`에 사실 76건과 관계 30건이 출처와 함께 들어 있다. `11_1차답과_남은확인.md`는 같은 내용을 대분류별로 읽기 좋게 풀고 해석과 남은 확인을 붙인 것이다.
- 조사 순서는 이렇게 한다.
  1. 11 파일의 "남은 확인"에 적힌 항목
  2. 사실 원장에서 근거 등급이 보도나 리서치팩인 행을 공식 자료로 다시 확인
  3. 회사별로 비어 있는 소분류
- 사실 원장에 공식 등급으로 이미 있는 내용은 다시 찾지 않는다. 수집한 원문에서 다른 내용이 나오면 고치고 보고한다.

### 새로 확인한 것을 넣는 곳

원본 데이터는 `조사틀과_관계도/data` 폴더의 파일 네 개다.

| 파일 | 내용 | 더하는 방법 |
|---|---|---|
| facts.csv | 출처가 있는 사실 | 행 추가. 열: 대분류, 소분류, 회사, 사실, 시점, 출처키 |
| relations.json의 SRC | 출처 | 키 추가. 값: [표시 이름, 주소, 근거 등급(공식, 보도, 리서치팩)] |
| relations.json의 N, E | 회사와 관계 | N: [id, 이름, 짧은 설명, 줄 번호 0~4, 세로 위치, 발행사면 1, 메모 목록]. E: [주는 쪽 id, 받는 쪽 id, 유형, 내용, 시점, 출처키] |
| notes.json | 대분류별 해석과 남은 확인 | read에 해석, todo에 남은 확인 |

- 관계 유형: acq 인수, inv 투자, ally 제휴와 협약, infra 보관과 청산 제공, supply 상품 공급, rival 경쟁, claim 회사가 내세운 협력(행사 동반, 파트너 명시처럼 약한 관계).
- facts.csv에는 출처가 있는 사실만 넣는다. 해석은 notes.json에 넣는다. 사실 문장은 명사형으로 끝내고, 숫자와 고유명사는 원문 표기 그대로 쓴다.
- 확인이 끝난 항목은 notes.json의 todo에서 지운다.
- 고친 뒤 `python 조사틀과_관계도/build.py`를 실행한다. `index.html`(조사 틀과 관계도 페이지)과 `out` 폴더의 문서 세 개가 다시 만들어진다. 출처키가 SRC에 없으면 실행이 멈추고 빠진 키를 알려 준다.
- 페이지 게시는 하지 않는다. 다시 만든 `index.html`을 산출물에 넣어 사용자에게 돌려준다.

### 메모 분류표와 조사 틀의 대응

읽기 담당이 메모에 붙이는 분류표는 그대로 쓰고, 정리 단계에서 아래처럼 옮긴다.

| 메모 분류표 | 조사 틀 |
|---|---|
| 연혁 | A 출신과 진입 |
| 상품, 구조, 숫자, 수수료 | B 상품 구조 |
| 지역제한, 고객 | C 최종 투자자 |
| 파트너 | D 유통과 접점, 또는 F 관계 |
| 인허가 | E 인가 |
| 용어 | 용어집(위키의 glossary) |
| 기타 | 해당 대분류가 없으면 버리지 말고 보고에 적음 |

### 기업별틀 엑셀과의 관계

- 기업별틀 엑셀의 조사항목은 이 조사 틀을 따른다. 엑셀 본문에는 설명에 필요한 것만 개조식으로 쓰고, 사실 원장과 출처는 엑셀이 아니라 위 데이터 파일에 둔다.
- Securitize와 tZERO는 담당자가 따로 있다. 조사 중에 나온 추가 질문만 정리해 넘긴다.
