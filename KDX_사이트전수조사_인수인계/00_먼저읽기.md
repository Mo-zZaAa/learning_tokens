# 먼저 읽기: 공식 사이트 전수 조사 인수인계

기준일 2026-11-16. KDX 해외 사례 리서치(Kraken, Robinhood, Binance, Dinari, Ondo, 미국 ATS)에서 공식 사이트를 빠짐없이 수집하기 위한 스킬, 스크립트, 그리고 이미 해둔 작업을 넘긴다.

## 0. 추가분에서 바뀐 것

먼저 보낸 zip 이후 달라진 점이다. 추가분 zip을 먼저 보낸 zip 위에 덮어쓰면 반영된다.

| 바뀐 것 | 내용 | 해당 파일 |
|---|---|---|
| 눌러야 바뀌는 화면 수집 | 표준 탭과 아코디언에 더해, 표시 없이 만든 누르는 카드와 전환 버튼도 누른다. 누른 것의 이름표를 붙여 받는다. 눌러서 다른 페이지로 넘어가면 그 주소를 장부에 올린다 | scripts/sitewiki.py, SKILL.md 3단계 |
| 역할 나누기 | 수집은 스크립트, 원문 읽기와 메모는 Haiku, 정리는 똑똑한 모델. 메모의 근거 구절을 원문과 기계로 대조하는 `verify` 명령 추가 | SKILL.md, agents 폴더(새로 생김), 02 파일 |
| 스크립트 보강 | `verify`, `fetch --refetch`, `fetch --click`, `plan --add` 추가. fetch가 시간 제한을 쪽 단위로 지키고 6쪽마다 저장. digest가 이전 묶음을 지우고 새로 만듦 | scripts/sitewiki.py |
| 재수집 | 세 회사의 첫 화면과 상품 화면을 새 규칙으로 다시 받음. 3번 표의 숫자 갱신 | work 폴더 |

추가분을 덮어쓴 뒤 세 회사에 `digest`를 한 번씩 실행해 읽기 묶음을 새로 만든다.

## 1. 한 줄 요약

- 스킬과 스크립트는 시험이 끝났다. Kraken, Dinari, Ondo 세 사이트에서 실제로 돌렸다.
- 해둔 것은 "목록화와 수집"까지다. 내용을 읽고 정리하는 일(notes, wiki, 기업별틀)은 아직 어느 회사도 하지 않았다.
- 같은 일을 다시 하지 않도록 4번과 5번을 먼저 본다.

읽고 정리한 내용이 아니라 수집 과정에서 드러난 구조다.

## 8. 이어서 하는 명령

스크립트 경로를 S, 작업 폴더를 W라고 하면:

```bash
# 추가분을 덮어쓴 직후 한 번: 읽기 묶음 새로 만들기
python S digest --work W/kraken
python S digest --work W/dinari
python S digest --work W/ondo

# Kraken, Ondo: 대기 0이 될 때까지 반복(8분씩). 끝나면 묶음 생성
python S fetch --work W/kraken --minutes 8
python S digest --work W/kraken

# 새 회사: map부터
python S map --work W/robinhood --domain robinhood.com --seed https://robinhood.com

# 메모를 쓴 뒤 검수, 위키를 쓴 뒤 누락 점검
python S verify --work W/dinari
python S audit --work W/dinari --wiki W/dinari/wiki
```

특정 구역만 먼저 받으려면 `--only 'https://www.kraken.com/press*'`처럼 범위를 준다. 이미 받은 화면을 다시 받으려면 `--refetch 'URL패턴'`.

## 9. 한계와 주의

- 읽기 담당을 Haiku로 돌리는 부분은 설계와 검수 명령까지 만들었고, 실제 Haiku 서브에이전트로 돌려 보지는 않았다. 첫 회사에서 묶음 두세 개만 먼저 맡겨 `verify.md`의 "원문에서 못 찾은 근거" 비율을 보고 나머지를 진행한다.
- 누르는 카드까지 받는 새 규칙은 11/16 저녁에 넣었다. 그 전에 받은 쪽 가운데 다시 받은 것은 세 회사의 첫 화면과 상품 화면이다. 나머지(Kraken 고객센터 글 23쪽과 약관 7쪽, Dinari의 문서, 블로그, 공시, Ondo의 docs)는 옛 규칙(표준 탭과 아코디언만) 그대로다. 글 형태 페이지라 영향은 작다. 상품 선택 카드나 전환 버튼이 있는 화면이면 `fetch --refetch`로 다시 받는다.
- 받지 못하는 것: 그래프 안의 점별 값, 마우스를 올려야 뜨는 풍선말, 값을 입력해야 결과가 나오는 계산기와 검색, 로그인이나 지갑 연결 뒤 화면.
- Kraken map은 스크립트 초기판으로 돌렸다. 그때는 호스트마다 사이트맵 파일을 400개까지만 열었다. www.kraken.com은 종목마다 사이트맵 파일이 하나씩 있어 그 수를 넘기 때문에 stocks 종목별 목록은 일부(448쪽)만 장부에 있다. 같은 틀이라 내용 조사에는 지장이 없다. 전체 종목 수는 사이트 본문이나 다른 출처로 확인한다.
- `inventory.csv`는 Kraken 기준 44MB다. 통째로 열지 말고 필요한 줄만 뽑는다.
- 수집일은 2026-11-16이다. 종목 수, 수수료, TVL처럼 바뀌는 값은 수집일 기준으로 적는다.
- raw와 files는 내부 작업용 원문 변환본이다. 밖으로 나가는 산출물에는 요약과 출처 링크만 쓴다.
- 공식 사이트 내용은 회사가 밝힌 내용이다. 인허가와 등록 사실은 감독기관 등록부로 따로 확인한다.
- robots.txt가 막은 경로, 로그인 화면, 내부용 호스트는 수집하지 않았고 앞으로도 하지 않는다.
- 이 스크립트는 Linux에서 시험했다. Windows나 Mac에서 처음 돌릴 때는 `--help`와 작은 범위(`fetch --limit 5`)로 먼저 확인한다.
